# Gallery sharing links

Gallery viewing is either listed, unlisted, coming soon, or hidden. Unlisted is an additional sharing setting on standalone D1 event galleries. It does not change the existing visibility status used by Android. In **Guest access → Gallery sharing**, save the unlisted setting and share the generated viewing URL. The identifier contains 256 cryptographically random bits. Requests without its matching token return 404; the gallery is omitted from public listings and the sitemap, and responses use no-store, noindex/nofollow, and no-referrer. Analytics is disabled on token pages. Automatic Worker invocation logs and traces are disabled to avoid persisting credential-bearing URLs; safe application error-category logs remain enabled. Individual photo sharing preserves the viewing token.

Anyone with the link can view and forward it. This is not private-file authorization: previously shared public image/download URLs remain accessible, including after replacing a viewing link. Replacing a viewing link revokes the old page link only. Hidden galleries still return 404 even with a valid viewing link. Curated MDX portfolio galleries cannot be made unlisted in this dashboard because their separate public case study and media would remain discoverable.

Guest submissions use a **separate submission link**. Enable submissions and save settings to generate it. Share it with attendees; their photos stay in the private pending bucket until owner approval. Replacing it revokes old submission links; disabling submissions closes this path. A viewing token never authorizes uploading, and neither token authorizes management. Existing named trusted invites keep their direct-publication behavior: anyone receiving or forwarding a trusted invite can publish photos, so distribute them carefully.

Guest passwords are retired. The legacy session endpoint returns 410 with guidance to request a submission link, and old cookies cannot authorize uploads. Existing Android app versions still offer a password setting: nonempty password updates return an actionable 400 directing the owner to the web dashboard. Android device pairing, management permission, uploads, known-file preflight, and existing gallery statuses remain unchanged. This is a documented guest-access change requested after the Effect migration; no Android release is claimed.

Migration 0007 is additive: existing galleries retain their listed/hidden status, all new tokens start NULL, and old password columns are retained for code rollback. No existing gallery is automatically exposed or converted. Production inspection before implementation found two D1 galleries (one published and one hidden) and zero enabled password-upload galleries. Owners explicitly opt in and obtain replacement links. Apply the migration to verified isolated preview bindings first, and to production before deploying the new code. Do not revert the schema or delete data on rollback. Rolling back to the old code restores password behavior, but the old version does not enforce unlisted page gating: disable/hide any newly unlisted galleries before such a rollback, or roll back to a version that retains the sharing guard. Keep native crypto password compatibility tests; production entry points no longer execute the expensive KDF. No Durable Object or paid service has been added.

Production deployment uses `npm run deploy:prod`, which requires clean `master` and explicitly selects production D1/R2 after the Astro build. The generated default configuration can contain preview D1 IDs; never deploy that mixed configuration directly. Preview deployment keeps its separate explicit preview binding script.
